# User Translate (Auto Translate) — 使用说明与后续构想

> 版本：1.2.1（本地版已包含 1.3 的按插件开关）
> 适用：Blender 4.1+，实测 4.5.9 LTS / Windows 11
> 许可：GPL-3（原项目作者 Bookyakuno，本版新增自动翻译与修复）

---

## 一、这个插件现在能做什么

一句话：**用一份 16 万条的社区词典，把第三方插件的英文界面换成中文，且不改动插件本身**。

### 1. 自动翻译（本版新增）

- **按插件勾选**：列表里列出你装的全部插件（当前 32 个），勾上就翻译，取消就恢复原文；
- **勾选即翻译**：没有词典的插件，勾上会自动抽取界面文字 → 查词典 → 生成词典 → 立即启用；
- **单行重翻（↻）**：插件更新后，点行尾的刷新按钮重建它的词典；
- **筛选与搜索**：`全部 / 翻译中 / 未翻译` + 关键词搜索（同时作用于列表）；
- **总开关**：一键停用全部翻译（给别人演示、排查问题时用）；
- **未命中提示**：翻译结果会告诉你 `提取 N 条 / 已翻译 M 条 / 待补 K 条`，待补的可以一键复制到剪贴板。

### 2. 手工流程（原版保留）

- 从 `.py` 文件或文件夹提取可翻译字符串（`bl_label` / `bl_description` / `name` / `description` / `text`）；
- 把文本贴到外部翻译网站，翻完粘回；
- 合并源文本与译文，生成 `user_files/<插件>.csv`。

### 3. 运行时机制

- 用 `bpy.app.translations.register()` 注册词典，**只在绘制界面时替换显示文字**；
- 插件代码、逻辑、数据完全不碰，卸载/停用即恢复原文；
- 需要 `偏好设置 → 界面翻译` 打开，语言选简体中文。

## 二、界面在哪、怎么用

1. `编辑 → 偏好设置 → 插件`，搜索 `User Translate`；
2. 展开后最上方就是「自动翻译」区块：

```
☑ 启用界面翻译（总开关）
生效词典：194 / 194 份
搜索: [____________]
[ 全部 ｜ 翻译中 ｜ 未翻译 ]
┌──────────────────────────────┐
│ ☑ Auto Mirror          已翻译 ↻│
│ ☐ BioVision (BVH)      未翻译 ↻│
│ ☑ Node Preview         已翻译 ↻│
│ ⋮                            │  ← 滚动条
└──────────────────────────────┘
[重翻选中] [全部启用] [全部停用]
☐ 覆盖已有 CSV
结果：…提取 48 条 / 已翻译 45 条 / 待补 3 条
```

3. 下面还有原版的手工流程区块、`语言` 选择、「文件数据」预览。

### 典型操作

| 想做的事 | 操作 |
|---|---|
| 让某个插件变中文 | 勾选它的方框 |
| 让某个插件恢复英文 | 取消勾选 |
| 全部恢复英文 | 取消「启用界面翻译」总开关 |
| 插件更新后刷新翻译 | 点该行右侧 ↻ |
| 只挑几个插件翻译 | 先搜索/筛选，再逐个勾选；其余可「全部停用」后单独开 |
| 修复坏词典 | 勾上「覆盖已有 CSV」，再点 ↻（旧文件自动备份 `.bak`） |

## 三、数据在哪、怎么备份

| 内容 | 位置 |
|---|---|
| 词典（一个插件一份） | `%APPDATA%\Blender Foundation\Blender\4.5\scripts\addons\user_translate\user_files\*.csv` |
| 词典格式 | 两列：`"中文","English"`，UTF-8 |
| 停用名单、筛选等设置 | Blender 用户偏好（`userpref.blend`）里 |
| 词典备份 | 覆盖模式下自动生成 `xxx.csv.bak` |
| 整包备份 | 直接复制 `user_translate` 整个文件夹 |

## 四、已知限制与常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 启动慢 5~6 秒 | 193 份词典 × 55 个翻译上下文 ≈ 1090 万条映射，全部在启动时注册。**这是下一步要优化的头号项**（见第五节） |
| 勾选后有几条没变 | 那几条词典里没有，属正常；用 `复制该插件的待补文字` 导出后补 |
| 某个插件界面变成奇怪的中文 | 它的词典列错位（社区词典通病）；勾「覆盖已有 CSV」+ ↻ 重建 |
| 勾选后要等几秒 | 首次为该插件生成词典；同一插件再次勾/取消是秒开的 |
| 和别的翻译插件冲突 | 两个插件都注册同名/同词条时以先注册者为准，建议只开一个 |
| 卸载后界面还是中文 | 停用插件并重启 Blender；若仍残留，检查是否还有别的翻译插件 |

## 五、头脑风暴：接下来能做什么

按「收益 ÷ 投入」排序，⭐ 是投入程度。

### A. 立刻可做（每项 1~3 小时）

1. **覆盖率显示** ⭐ — 列表每行显示 `45/48` 这类已翻译比例，一眼看出哪些插件翻得完整。
2. **词典查看器** ⭐⭐ — 点某行 → 弹出该插件词典内容（可搜索、可编辑），不用去翻文件夹。
3. **词典体检** ⭐⭐ — 扫描全部 CSV，报告：列错位、中英颠倒、重复源词条、空译文；支持一键重建。
4. **日志文件** ⭐ — 把注册失败、跳过文件等写到 `user_files/diagnostics.log`，方便反馈问题。
5. **译文冲突报告** ⭐⭐ — 同一英文串在不同词典里译法不同（如 "Apply" → 应用/应用修改/套用），列出来让你统一。

### B. 值得做（半天级）

6. **机翻补翻** ⭐⭐⭐ — 未命中词条批量走 DeepSeek/OpenAI 兼容接口（按需、可关、按条计费），命中率从 ~90% 提到 ~99%。注意：需要 API Key，且会产生费用。
7. **启动懒加载** ⭐⭐⭐ — 只注册「勾选中的插件」词典，其余按需加载。默认只开用户勾选的，启动从 5.7s → 0.3s 量级。**推荐优先做**。
8. **自动发现新插件** ⭐⭐ — 检测到新装插件时提示「要翻译吗？」，避免每次手动刷新。
9. **个人术语表** ⭐⭐ — 用户自定义优先词条（如 Rig → 绑定），覆盖社区词典，保证多插件术语一致。
10. **导出/导入个人词典** ⭐⭐ — 把你整理好的翻译打包分享给别人。

### C. 大件（需要设计）

11. **Blender 扩展包格式** ⭐⭐⭐ — `blender_manifest.toml` + 扩展平台发布，支持一键安装/更新。
12. **上下文级翻译** ⭐⭐⭐ — 目前一条词条注册到所有 context；改为按 context 精确注册，可解决同词不同义，并能降低内存。
13. **翻译版本追踪** ⭐⭐⭐ — 插件升级后对比界面字符串变化，提示「新增 3 条 / 失效 2 条」。
14. **增量词典** ⭐⭐⭐ — 只存差异，多个插件共享同一份基础词表，体积和内存大幅下降。
15. **翻译质量评分** ⭐⭐⭐ — 对每条译文做启发式打分（长度比、CJK 比例、重复词），自动标记可疑条目。

### D. 体验类

16. 列表行内直接改名/隐藏某些插件（不翻译但也别显示）。
17. 快捷键：`Ctrl+Shift+T` 切换总开关。
18. 按插件分类/作者筛选。
19. 翻译预览：勾选前先告诉你「这个插件有 48 条会被替换」。
20. 与官方扩展市场联动，自动抓取社区新词典。

## 六、我的推荐路线（如果只做三件事）

1. **启动懒加载（第 7 项）** — 收益最大：现在每次启动 Blender 都要多花 5~6 秒，改成「只加载勾选的」后几乎无感，而且顺带降内存。
2. **覆盖率显示 + 词典体检（第 1、3 项）** — 让「哪些插件翻得完整」「哪份词典是坏的」一眼可见，减少你手动排查。
3. **机翻补翻（第 6 项）** — 把命中率从 ~90% 拉到接近 100%；做成可选、需要 API Key，不用就不花钱。

第 11 项（扩展包格式）等你决定要把这个发给更多人时再做，它能解决「怎么更新」的问题。

## 七、当前技术债（记录备查）

- `register_translation_dict()` 一次性注册全部词典，无缓存、无懒加载；
- 词典按「每个上下文一份」注册，条目数 ×55，内存占用高；
- 停用名单存在 `disabled_dicts`（换行分隔字符串），没有独立的 UI 管理页；
- UIList 的 `↻` 与 `重翻选中` 两个入口功能重叠，可合并；
- 原版遗留的手工流程 UI（提取/剪贴板/合并）文案仍是英文，未本地化。
